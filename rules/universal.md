1. **Route first.** Use the Context Router table above before loading any data file. Do not guess; the router exists to avoid guessing.
2. **Load lazily, search first.** Never load all L3 files at once. Max 2 hops: router → L2 narrative → (optional) L3 data. An entry directory is searched, not read whole: `rg -l '<term>' <dir>/` matches entry bodies, then read only the hits. The filename carries the title alone, so fall back to the listing only when the task has no term worth searching. If the task is answerable from L2 alone, stop there.
3. **One file per entry.** Ledger entries live one per file in an entry directory. A new entry is a new file; never edit or extend an entry someone else wrote. When an entry becomes obsolete, set `status: archived`; do not delete.
4. **Rationale required.** ADRs and decisions must include *why*. An entry without a reason will rot.
5. **Search before write.** Before adding an entry, grep the target directory for a duplicate or near-duplicate. Update or supersede rather than create a duplicate.
6. **Existing patterns win.** Read `{{CONTEXT_DIR}}/design-patterns/DESIGN-PATTERNS.md` before introducing a new convention. If an existing pattern covers the case, use it.
7. **IDs are timestamps.** All L3 entries use the format `{type}_{YYYYMMDD}_{HHMMSS}_{4hex}` where `{type}` is the schema prefix declared in the directory's `_schema.md`. The entry filename is `{id}__{slug}.md`, so the directory listing sorts chronologically and reads as a title index (titles only), which is why rule 2 greps the bodies instead.
8. **Context update as final task.** When planning work with a todo list, always add a final step: "Evaluate context update." At that step, walk the §Self-Update Rules table below and decide if any entry should be captured. If nothing qualifies, skip. Do not create entries just to fill the step.
